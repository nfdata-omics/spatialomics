# Cell2location deconvolution

## Objective and scope

Integrate Cell2location deconvolution into the SpatialData-centred workflow while:

- training the single-cell reference once per pipeline run;
- training one spatial model jointly across all slides in the pipeline run;
- returning posterior results to the corresponding per-sample SpatialData;
- retaining posterior results and provenance in SpatialData;
- separating expensive inference from lightweight plotting and reporting;
- keeping detailed diagnostics outside MultiQC and a concise summary inside it.

The feature currently supports one single-cell reference dataset per pipeline
run. Support for multiple reference datasets is not yet implemented.

Relevant implementation files are:

- [`main.nf`](../../main.nf);
- [`workflows/spatialomics.nf`](../../workflows/spatialomics.nf);
- [`modules/local/cell2location/reference/`](../../modules/local/cell2location/reference/);

## Agreed behaviour

### Activation and data flow

The presence of `single_cell_reference_h5ad` enables the complete Cell2location
branch; there is no separate skip flag. Without a reference, the QC-annotated
SpatialData continues directly downstream.

With a reference:

1. `CELL2LOCATION_REFERENCE` trains one reference model and exports signatures;
2. the QC-annotated spatial tables from all slides are collected while preserving
   each sample ID and SpatialData association;
3. `CELL2LOCATION_DECONVOLUTION` uses the signatures to train one spatial model
   jointly across all slides and exports one posterior-result artifact per sample;
4. one lightweight reintegration process adds every posterior result to the
   corresponding QC-annotated SpatialData and renders the joint training plots;
5. `CELL2LOCATION_PLOTS` produces per-sample posterior diagnostics, biological plots
   and MultiQC inputs;
6. the deconvolved SpatialData becomes the input to segmentation augmentation;
7. the most advanced available SpatialData is emitted and published by the workflow.

All slides in one pipeline run form one joint spatial model. Pipeline runs are
expected to contain a coherent project-level set of no more than approximately
24 slides generated by the same service, with compatible technology, resolution
and preprocessing. Grouping one run into multiple independent spatial models is
not currently in scope.

The spatial model is not saved separately. Nextflow caching is relied upon to
avoid repeating successful GPU inference. Plotting remains a separate process
so plot changes do not invalidate deconvolution tasks.

### Reference contract

The reference is an H5AD containing raw counts and cell-type annotations. The
pipeline interface is intentionally tool-independent:

| Parameter                             | Default     | Contract                                  |
| ------------------------------------- | ----------- | ----------------------------------------- |
| `single_cell_reference_h5ad`          | `null`      | Existing reference H5AD                   |
| `single_cell_reference_cell_type_key` | `cell_type` | Cell-type column in `obs`                 |
| `single_cell_reference_batch_key`     | `none`      | Batch column in `obs`; `none` disables it |
| `single_cell_reference_counts_layer`  | `X`         | Raw counts in `X` or a named layer        |
| `single_cell_reference_gene_key`      | `var_names` | Gene IDs in `var_names` or a `var` column |

The reference model is trained once. Its signatures CSV is published under
`${params.outdir}/deconvolution/` and broadcast to all spatial samples. The
trained reference model remains in the process output/cache but is not currently
published.

### Spatial input and inference

The deconvolution inputs are the QC-annotated SpatialData tables from all samples,
selected by `bin_analysis_bin_size` (`square_016um` by default). Only locations
with `obs['qc_pass'] == true` are included in the joint model; other locations
remain in their original tables with missing posterior values.

Each selected spatial table is represented by a temporary AnnData containing
only data required by Cell2location. Before concatenation, the implementation
must preserve the sample ID and original observation ID and assign globally
unique observation names. Duplicate sample IDs and duplicate observation IDs
within a sample are errors.

The joint gene set is the intersection between the reference signatures and all
spatial samples. Its order follows the reference-signature index. The number of
input genes per sample and the final shared-gene count are reported, and the
configured minimum shared-gene threshold applies to this joint set. Missing genes
are not silently filled with zero.

The temporary AnnData objects are concatenated and registered using the sample ID
as the Cell2location `batch_key`. This allows slide-specific technical detection
sensitivity to be represented while fitting one shared spatial model. Complete
SpatialData objects, images and masks are not concatenated or passed to the model.

Spatial counts are read from `X`. `spatial_gene_key` defaults to `var_names`.
Reference and spatial gene IDs must be unique and at least 1,000 genes must be
shared by default. Failure messages report examples and alternative overlaps
when `var_names` or `gene_ids` are available.

Spatial-model training uses a default batch size of 25,000 locations,
chosen for the facility GPUs. It remains overridable with module-level
`--batch-size`. Posterior sampling uses the independent
`--posterior-batch-size` setting, with a default of 2,048, to control peak
sampling memory.
The joint-model design does not change the training batch size: observed GPU
memory use is dominated by this setting, and it must not be increased merely
because multiple slides are trained together.

The posterior batch size is not expected to match the training batch size.
Posterior sampling draws `posterior_num_samples` values for location-specific
latent variables and can therefore have a substantially different memory
profile. The value of 2,048 follows the documented Cell2location default and can
improve throughput relative to the previous conservative value of 512. GPU and
host-memory use during complete joint posterior export must be reviewed during
functional validation.

`detection_alpha` controls regularisation of location-specific detection
sensitivity around the batch mean. The pipeline default is 200, applying strong
regularisation appropriate when total RNA variation is expected to be explained
largely by true variation in cell density. A value of 20 remains available to
allow substantially more within-slide technical variability. Evaluation of this
default should compare representative fits at 200 and 20 against an independent
histological or segmentation-based estimate of cell density and inspect total
counts, inferred total abundance and detection sensitivity across each slide.
ELBO alone is not treated as sufficient evidence for choosing this prior.

After posterior export, the joint result is split by sample ID. Original
observation IDs are restored and one lightweight posterior-result artifact is
produced per sample. One lightweight process receives all posterior artifacts and
original QC-annotated SpatialData objects, joins them by explicit sample ID and
performs the final reinsertion for every sample.

## SpatialData contract

The selected table stores labelled cell-type abundance matrices in `obsm`:

- `means_cell_abundance_w_sf`;
- `stds_cell_abundance_w_sf`;
- `q05_cell_abundance_w_sf`;
- `q95_cell_abundance_w_sf`.

Rows are aligned to the complete spatial table. Locations excluded by QC contain
`NaN`. No permanent `c2l_<celltype>` or total-abundance columns are added to
`obs`, because choosing one posterior estimator is analysis-dependent.

When available, detection-sensitivity summaries are stored in `obs` as:

- `c2l_detection_sensitivity_mean`;
- `c2l_detection_sensitivity_std`;
- `c2l_detection_sensitivity_q05`;
- `c2l_detection_sensitivity_q95`.

`uns['cell2location']` stores provenance, model settings, cell-type names,
location and gene counts, training history, ELBO summaries, posterior-sampling
settings and compact reconstruction-QC data or its error state.

For a joint model, this metadata additionally records that inference was joint,
the complete canonically ordered sample list, total modelled locations across all
samples, the current sample ID and its modelled-location count, the common gene
set size, and the sample batch key. Compact global model metadata may be
duplicated in each output SpatialData to keep each final result self-contained;
large joint intermediates must not be duplicated.

## Output and reporting contract

### Deconvolution outputs

Joint inference produces one posterior-result artifact per sample. The single
lightweight reintegration process then preserves the established per-sample outputs:

```text
<sample>_cell2location.zarr/
<sample>_cell2location_abundance_mean.csv
<sample>_cell2location_abundance_q05.csv
```

The CSV files are published under `${params.outdir}/deconvolution/`. Each Zarr is
passed downstream and included in the final published SpatialData rather than
published independently by the module. The workflow-facing reintegration output
retains the existing `[meta, zarr]` tuple contract so downstream segmentation,
plotting and final publication remain sample-oriented.

### Selected abundance statistic

`cell2location_abundance_statistic` selects the point estimate used for
biological plots and tables:

- `mean` (default): `means_cell_abundance_w_sf`;
- `q05`: `q05_cell_abundance_w_sf`.

Posterior diagnostic plots are independent of this selection. Total abundance
is the sum across cell types. Fractions are abundance divided by total abundance;
zero-total locations remain masked. Whole-slide composition is calculated from
summed abundance, not from the unweighted mean of location-level fractions.

When `q05` is selected, derived totals and fractions are normalised marginal
`q05` estimates, not posterior fifth percentiles of those derived quantities.

### Per-sample plot outputs

`CELL2LOCATION_PLOTS` publishes per-sample outputs under
`${params.outdir}/deconvolution/<sample>_cell2location/`:

- a compact diagnostics TSV;
- posterior mean-versus-`q05` hexbin PDF;
- spatial relative posterior interval-width PDF;
- cell-type abundance PDF;
- cell-type fraction PDF;
- dominant cell-type spatial-map PDF;
- total-abundance distribution and spatial-map PDF;
- compact deconvolution PNG for MultiQC;
- composition and summary custom-content TSV files for MultiQC.

Training history and model-wide reconstruction diagnostics belong to the joint
model and are produced once in the root deconvolution output directory rather
than duplicated for every sample. Sample-specific reconstruction summaries may
remain with the per-sample outputs when they are computed from that sample's
locations.

`CELL2LOCATION_DECONVOLUTION` writes the raw joint-model diagnostic artifacts,
including the training-history CSV and compact reconstruction/QC data.
`CELL2LOCATION_REINSERT`, which is invoked once for the complete joint-model
result, consumes those artifacts and creates the training-history/ELBO figure and
model-wide diagnostic figures while reinserting the per-sample results. Both raw
data and rendered plots are published under
`${params.outdir}/deconvolution/`. Plot-only changes therefore do not
invalidate the GPU inference task.

Available tissue imagery is rendered in greyscale. Cell-type abundance and
fraction panels use the perceptually uniform sequential `magma` colormap with zero
as the lower bound. Abundance panels share one scale based on the largest
cell-type 99th percentile. Fraction panels use an independent 99th-percentile
maximum. Relative posterior interval-width panels also use `magma`, share one
robust scale and mask posterior means at or below
`cell2location_uncertainty_min_abundance` (`0.1` by default).

The dominant cell-type map uses the selected abundance statistic to calculate
within-location fractions. Each modelled location is assigned to the cell type
with the largest fraction. Colour identifies that cell type and colour intensity
or opacity represents its fraction, so mixed locations appear less strongly
assigned. To keep the map and legend interpretable, at most ten cell types are
shown individually. They are selected by the number of locations in which they
are dominant, rather than by total slide abundance; remaining dominant types are
grouped as `Other`. The plot is published with the extended per-sample outputs
and is not currently included in MultiQC.

### MultiQC

MultiQC receives:

- a cross-sample bar plot of whole-slide cell-type composition;
- a cross-sample table with modelled locations, total abundance, and mean and
  median abundance per location;
- one compact per-sample image showing total abundance and the composition of up
  to three selected cell types.

`cell2location_multiqc_cell_types` optionally selects up to three types. Its
default is `null`, which selects the three most abundant types independently per
sample. Selected fractions are mixed using pink, cyan and yellow. For each
location, their relative proportions after normalisation to the selected total
determine the mixture hue. The unselected fraction is retained as a separate
coverage quantity and controls saturation using the square root of selected
coverage. This nonlinear scaling keeps low-to-moderate selected fractions visible
without presenting them as complete composition. Saturation is implemented by
blending the mixture hue with a light neutral grey (`#e0e0e0`); it is not encoded
as low shape opacity, which would allow the microscopy background to dominate.
Locations with no selected abundance remain light grey. The shapes use a high,
fixed opacity over the greyscale tissue image. The reported whole-slide selected
coverage remains in the panel subtitle.

`ASSEMBLE_SPATIAL_MULTIQC` groups independently available QC, imaging,
segmentation and deconvolution images by sample. It publishes
`<sample>_spatial_mqc.html` under `${params.outdir}/spatial_plots/`. Missing
segmentation or deconvolution content does not suppress other spatial content.

## Non-obvious decisions and rationale

- Keep all posterior summaries rather than selecting `mean` or `q05` at
  inference time, so downstream analyses can choose an estimator explicitly.
- Keep Cell2location matrices in the AnnData table inside SpatialData rather
  than passing a parallel AnnData representation through the workflow.
- Train the reference once and broadcast signatures, avoiding repeated training
  for every slide.
- Train the spatial model jointly across the coherent set of slides and use the
  sample identity as a batch, following the validated project-level analysis
  approach represented by the development notebooks.
- Split posterior results only after joint inference; this is not a separate
  per-slide application of the trained spatial model.
- Keep GPU inference separate from SpatialData reintegration so a
  lightweight write or association failure does not require repeating training.
- Associate results by explicit sample ID, never by channel emission order.
- Separate inference and plotting because GPU tasks are expensive and plot
  development should remain resumable independently.
- Store a compact reconstruction histogram rather than full expected-count
  matrices to limit SpatialData size.
- Keep detailed posterior diagnostics outside MultiQC; MultiQC is limited to
  cross-sample summaries and one compact image per sample.
- Add high-resolution microscopy and segmentation only after deconvolution, so
  expensive inference does not stage or copy the largest image layers.

## Joint-model implementation

1. `CELL2LOCATION_DECONVOLUTION` is a single joint GPU task. Its interface
   receives paired sample IDs and QC-annotated SpatialData paths
   together with the reference signatures. The implementation sorts these
   pairs canonically by sample ID before concatenation to stabilise stochastic
   minibatch order, provenance and task caching. Correctness and posterior
   splitting still rely on explicit sample labels, never on list position after
   concatenation.
2. The Python inference script validates every sample, calculates the common gene
   set, builds the concatenated QC-pass AnnData, registers the sample ID as
   `batch_key`, trains once and exports the posterior once.
3. It writes one lightweight H5AD posterior artifact per sample. Each contains
   original observation IDs, labelled posterior abundance matrices, detection
   sensitivity and the identifiers needed for safe reinsertion, but no spatial
   count matrix, image or mask. A separate manifest records the expected sample
   IDs, files and sample dimensions, while the joint diagnostics JSON records
   model settings and global provenance.
4. `CELL2LOCATION_REINSERT` is one lightweight process for the complete set of
   samples. It joins posterior artifacts to original QC SpatialData by
   sample ID, fails on duplicates or missing matches, renders the joint-model
   training and reconstruction plots, and preserves the current per-sample
   deconvolved Zarr and abundance-CSV outputs. The workflow expands those
   outputs back into keyed per-sample channels.
5. `CELL2LOCATION_PLOTS` remains sample-oriented and receives the reinserted
   Zarrs. It retains only genuinely sample-specific diagnostics in each sample directory;
   the shared training history and model-wide reconstruction diagnostics are
   produced by `CELL2LOCATION_REINSERT`.
6. The reintegrated `[meta, zarr]` channel is routed into the existing segmentation,
   final SpatialData, MultiQC and publication paths. The no-reference branch will
   remain unchanged.
7. Module metadata, stubs, output documentation and this specification describe
   the final interfaces. Realistic GPU and end-to-end validation remains user-run.

## Implementation and verification status

### Implemented

- input-driven optional reference branch;
- single reference training and signature reuse;
- QC-aware joint multi-slide spatial-model training with sample as batch;
- lightweight posterior artifacts and keyed reinsertion into per-sample SpatialData;
- posterior and provenance storage in SpatialData;
- single joint-model training/reconstruction diagnostics;
- per-sample posterior diagnostics and biological plots, including dominant cell type;
- MultiQC TSV and compact-panel integration;
- propagation into the final SpatialData and optional segmentation augmentation.

### Checked statically

- Python syntax for the Cell2location scripts;
- Nextflow configuration parsing and pipeline help initialisation;
- YAML parsing for module metadata and MultiQC configuration;
- whitespace and patch integrity checks.

### Functionally validated

An end-to-end local Docker run with the `test` profile and the
`crc_coarse_5k.h5ad` reference completed successfully on 2026-11-04. The run
executed reference training, joint-model inference, reinsertion, all per-sample
Cell2location plots, segmentation augmentation, spatial MultiQC assembly and
MultiQC itself. It produced the expected joint diagnostics, abundance tables,
dominant-cell-type plot, compact MultiQC image and final report. Reinsertion also
completed without nullable-string write errors for this dataset.

This run contained one spatial sample. It validates the complete execution path
and single-sample special case of the joint implementation, but not concatenation,
posterior splitting and association across multiple spatial samples. Visual and
scientific review of the dominant-cell-type map and revised MultiQC colour mixture
on representative production slides also remains to be completed.

## Open questions

- Multiple reference H5ADs are not implemented. The unresolved contract is
  whether each sample/reference pair should produce its own final SpatialData,
  remain a separate deconvolution output, or be merged with namespaced keys.
- Figure pagination and MultiQC readability should be reviewed for references
  containing many cell types.
- The dominant cell-type spatial map may replace or complement the current
  three-cell-type mixture panel in MultiQC after its readability has been
  evaluated on representative references and slides. The appropriate maximum
  number of displayed types and handling of `Other` should be reviewed at that
  stage.
- A future grouping field could assign samples to project-defined deconvolution
  groups. The workflow would then train one joint spatial model per group and run
  groups independently or in parallel. This would support heterogeneous sample
  subsets within one pipeline run without weakening explicit sample-to-result
  associations. The grouping source, validation rules and output namespace are
  not yet defined.
